# 成员A · 后端工程师 — 任务说明

> **你的职责：** 搭建 FastAPI 后端服务，提供全部 API 接口，通过 `orchestrator.py` 编排调度 C 和 D 的 AI 模块。你是系统的骨架——前端发来的请求 → 你调度 AI 模块 → 把结果返回前端。
>
> **代码获取：** 具体代码片段见 `docs/08_代码速查手册_Code_Cheatsheet.md` 第一节（A · 后端代码）。Pydantic 模型定义见协议文档第 2 节。

> **关键约束：** 你是唯一能串起 C 和 D 的人。所有 Python 模块间的调用通过你 import 完成。`backend/schemas.py` 是 A/C/D 共享的数据合同。

#### 任务 5.2：Chat SSE 对接 C（关键）

**要求：**
- 在 `main.py` lifespan 中创建 `IntentAnalyzer` 单例，注入到 chat router
- `routers/chat.py` 实现 SSE 流：
  - 接收 `ChatRequest` → 加载对话历史 → 调 `intent_analyzer.analyze(session_id, messages)`
  - `is_complete=False` → 发送 `event_type: "question"` 的 ChatEvent
  - `is_complete=True` → 发送 `event_type: "confirm"` 的 ChatEvent
  - 最后发送 `data: [DONE]\n\n`
- SSE 格式：`data: {json}\n\n`（每条消息后有空行，兼容标准 SSE）
- `StreamingResponse`：media_type="text/event-stream"，headers 含 `Cache-Control: no-cache`

**验证：** Postman（或 curl）调 Chat API → 返回 SSE 流 → 能看到 question/confirm 事件。

### Day 7 — orchestrator.py 核心调度（Step 1-4）（关键日）

#### 任务 7.1：理解 orchestrator 流程

**要求：** `services/orchestrator.py` 是整个项目最重要的文件。它按以下顺序调度：

```
Step 1: lock_intent(session_id)           → C: 锁定教师确认的意图
Step 2: RAGRetriever.search(query)        → C: 知识库检索
Step 3: 解析参考资料                       → D: extract_pdf_text / summarize_video 等
Step 4: KnowledgeFuser.fuse(intent, rag, refs) → C: 三路融合 → GenerationInstruction
Step 5: gen_ppt(instruction)              → D: 生成 .pptx
Step 6: gen_doc(instruction)              → D: 生成 .docx
Step 7: gen_animation(instruction)        → D: 生成 .html
Step 8: 注册输出文件 → 更新 Task 为 completed
```

**Day 7 先完成 Step 1-4**（Step 5-7 需要 D 的函数就绪，Day 8 做）。

---

#### 任务 7.2：写 Orchestrator 类

**要求：**
- `__init__(config)`：初始化 IntentAnalyzer / RAGRetriever / KnowledgeFuser 三个单例
- `run_generation(session_id)` → `TaskInfo`：
  - Step 1：`intent_analyzer.lock_intent(session_id)` → IntentResult
  - Step 2：构造 query = teaching_goal + 所有 knowledge_point.title → `rag_retriever.search(query, top_k=5)`
  - Step 3：遍历 session 的上传文件 → 根据 file_type 调 D 的解析函数 → 封装为 ReferenceMaterial 列表
  - Step 4：`fuser.fuse(intent, rag_docs, references)` → GenerationInstruction
- 每步失败 → 更新 Task status=failed + error 描述 → 不继续后续步骤

**验证：** 手动调 `run_generation()` → Step 1-4 不报错 → 打印中间结果截图。
