# 09 — 功能模块划分与开发总览

> 版本 v2.0 | 2026-07-20 | 工期：7月22日 → 8月22日（一个月）
> 核心思路：**以用户可见的功能模块（纵向）组织开发，不以技术层（横向）划分。**
> 每个模块有 Owner，Owner 对该模块的端到端交付负责。

### M1 — 会话与对话引导

> **用户故事：** 教师输入"我想备一节Python列表的课"→ AI 追问授课对象、课时 → 教师回答 → AI 确认总结 → 教师确认。

| 维度 | 内容 |
|------|------|
| **Owner** | **陈澜** |
| **涉及人员** | 陈澜(意图引擎) + 姜文杰(Chat API + Session API) + 潘卓然(对话UI) |
| **输入** | 用户文本消息 |
| **输出** | IntentResult（结构化教学意图，含知识点、流程、风格） |
| **前置依赖** | 无（可最先开发） |
| **目标完成** | **8月2日** |

**子任务清单：**

| # | 子任务 | 执行人 | 产出文件 | 验收标准 |
|---|--------|--------|---------|---------|
| 1.1 | 意图分析引擎（analyzer + 状态机） | 陈澜 | `ai/intent/analyzer.py`, `state.py` | 模糊输入 → 结构化 IntentResult JSON |
| 1.2 | Prompt 模板（提取/追问/确认） | 陈澜 | `ai/prompts/intent_extract.txt`, `follow_up.txt`, `confirm.txt` | 每个 Prompt 单独测试通过 |
| 1.3 | Session API（创建/查询/列表） | 姜文杰 | `backend/routers/session.py`, `models/session.py` | Postman 测试 CRUD 全通 |
| 1.4 | Chat SSE API（流式对话） | 姜文杰 | `backend/routers/chat.py` | SSE 流式返回 question/confirm 事件 |
| 1.5 | 对话页面 UI（气泡 + 追问卡片 + 确认面板） | 潘卓然 | `Chat.vue`, `MessageBubble.vue`, `QuestionCard.vue`, `ConfirmPanel.vue` | 假数据渲染 3 轮对话正常 |
| 1.6 | SSE 流式解析 + 打字机效果 | 潘卓然 | `utils/sse.js` | 真实 SSE 流 → 逐字渲染 |
| 1.7 | 对话状态管理（Pinia store） | 潘卓然 | `stores/session.js` | 消息列表、追问状态正确 |

**Owner 职责（陈澜）：**
- 驱动 M1 从 7/22 到完成（8/2）
- 确保 `IntentAnalyzer.analyze()` 被姜文杰正确调用
- 验收潘卓然的对话 UI 能正确渲染 question/confirm 两种事件
- 与姜文杰联调 SSE 流 → 与潘卓然联调前端渲染

### M2 — 文件上传与多模态解析

> **用户故事：** 教师拖拽 PDF/Word/图片/视频到上传区 → 显示缩略图和解析状态 → 后端提取文本内容供 M5 使用。

| 维度 | 内容 |
|------|------|
| **Owner** | **赵钰洁** |
| **涉及人员** | 赵钰洁(解析器) + 姜文杰(上传API + 文件管理) + 潘卓然(上传组件) |
| **输入** | 文件二进制 + ref_description |
| **输出** | FileInfo + ReferenceMaterial（解析后文本） |
| **前置依赖** | M1（需要 session_id 关联文件） |
| **目标完成** | **8月1日** |

**子任务清单：**

| # | 子任务 | 执行人 | 产出文件 | 验收标准 |
|---|--------|--------|---------|---------|
| 2.1 | PDF 文本提取 | 赵钰洁 | `gen/parse/pdf.py` | 教材 PDF 提取前 500 字，中文正常 |
| 2.2 | Word 文本提取 | 赵钰洁 | `gen/parse/doc.py` | 教案 Word 提取，标题层级保留 |
| 2.3 | 图片描述（DeepSeek Vision / OCR） | 赵钰洁 | `gen/parse/image.py` | 含文字截图 → 返回描述含图中文字 |
| 2.4 | 视频关键帧提取 + 摘要 | 赵钰洁 | `gen/parse/video.py` | MP4 → 关键帧 JPG + 200 字摘要 |
| 2.5 | 文件上传 API（校验 + 存储） | 姜文杰 | `backend/routers/file.py`, `services/file_mgr.py` | 5 种格式各上传一个全部成功 |
| 2.6 | 文件 ORM 模型 + DB 记录 | 姜文杰 | `backend/models/file.py` | 上传后 data.db 有记录 |
| 2.7 | 拖拽上传组件 + 文件列表 + 进度条 | 潘卓然 | `FileUploader.vue` | 拖拽 PDF → 进度条 → 列表显示 FileInfo |
| 2.8 | 上传后异步解析（后台任务） | 姜文杰 | `services/file_mgr.py` | 上传成功 → 返回 FileInfo → 后台调赵钰洁解析 |

**Owner 职责（赵钰洁）：**
- 驱动 M2 从 7/22 到完成（8/1）
- 确保 4 个解析函数能被陈澜（fusion.py）正常 import

- 验收潘卓然的上传组件 UI 交互流畅

### M3 — 知识库与RAG检索

> **用户故事：** 陶克钦收集教材/教案 → 运行 build_kb.py → ChromaDB 入库 → M5 生成课件时自动检索相关知识。

| 维度 | 内容 |
|------|------|
| **Owner** | **陈澜** |
| **涉及人员** | 陈澜(RAG全链路) + 陶克钦(资料收集) |
| **输入** | knowledge-base/ 目录下的 PDF/Word/txt |
| **输出** | RAGDocument 列表（检索结果，含 content + source + score） |
| **前置依赖** | M2（loader 调赵钰洁的解析函数） + 陶克钦的资料收集 |
| **目标完成** | **8月3日** |

**子任务清单：**

| # | 子任务 | 执行人 | 产出文件 | 验收标准 |
|---|--------|--------|---------|---------|
| 3.1 | 知识库资料收集整理 | 陶克钦 | `knowledge-base/` 目录 | 5 类资料各 ≥ 目标数量 |
| 3.2 | 文档加载器 | 陈澜 | `ai/rag/loader.py` | 遍历 knowledge-base/ → 加载全部文档 |
| 3.3 | 文本分割（中文友好） | 陈澜 | `ai/rag/splitter.py` | chunk_size=500, overlap=50 |
| 3.4 | 向量化 + ChromaDB 入库 | 陈澜 | `ai/rag/embedder.py` | 入库后 chroma_data/ 目录存在 |
| 3.5 | 检索器（RAGRetriever 类） | 陈澜 | `ai/rag/retriever.py` | search("Python列表", top_k=3) → 3 条相关结果 |
| 3.6 | 一键构建脚本 | 陈澜 | `ai/build_kb.py` | 陶克钦能独立运行 |
| 3.7 | 检索准确率验证 | 陶克钦 | `知识库资料清单.xlsx` | 5 个查询 × top3，Precision@3 ≥ 60% |

**Owner 职责（陈澜）：**
- 驱动 M3 从 7/22 到完成（8/3）
- 确保 `RAGRetriever.search()` 能被姜文杰正确 import
- 把 `build_kb.py` 交给陶克钦并教会运行
- 与陶克钦协作验证检索质量

| **输出** | .pptx + .docx + .html 文件 + TaskInfo |
| **前置依赖** | M1（IntentResult）+ M2（ReferenceMaterial）+ M3（RAGDocument） |
| **目标完成** | **8月12日** |

**子任务清单：**

| # | 子任务 | 执行人 | 产出文件 | 验收标准 |
|---|--------|--------|---------|---------|
| 5.1 | PPT 样式系统（颜色/字体/边距常量） | 赵钰洁 | `gen/pptx/layout.py` | 常量定义完整，字号/颜色体系合理 |
| 5.2 | PPT 页面模板（封面/目录/内容/总结） | 赵钰洁 | `gen/pptx/slides.py` | 4 种页面各生成一页 → 排版正常 |

| 5.6 | Prompt 模板（PPT大纲/内容/教案/动画） | 赵钰洁 | `gen/prompts/*.txt` | 每个 Prompt 单独测试通过 |

## 六、模块间接口契约（关键！）

### 6.1 模块间数据流

```
M1 输出 IntentResult ─────────────┐
M2 输出 ReferenceMaterial[] ──────┤
M3 输出 RAGDocument[] ────────────┤
                                   ▼
                          M5 陈澜 KnowledgeFuser.fuse()
                                   │
                                   ▼
                          GenerationInstruction
                                   │
                    ┌──────────────┼──────────────┐
                    ▼              ▼              ▼
              赵钰洁 gen_ppt()  赵钰洁 gen_doc()  赵钰洁 gen_animation()
                    │              │              │
                    ▼              ▼              ▼
                 .pptx          .docx          .html
                    │              │              │
                    └──────────────┼──────────────┘
                                   ▼
                            M6 预览 / M7 下载
```

### 6.2 接口类型定义

所有模块间传递的数据类型定义在 `backend/schemas.py`，由姜文杰维护。陈澜和赵钰洁通过 `from backend.schemas import ...` 使用。

### 6.3 接口变更流程

1. 发现现有接口不满足需求 → 先在团队群提出
2. Owner 评估影响范围："谁依赖这个接口？"
3. 姜文杰更新 `backend/schemas.py` + 协议文档
4. 通知所有下游消费者同步更新
5. 陶克钦验收变更后的两端对齐
